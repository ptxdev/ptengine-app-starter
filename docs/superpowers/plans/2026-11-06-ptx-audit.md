# ptx audit（规则层）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 app-starter 加一条 `npm run audit` / `ptx audit`：对项目源码做确定性静态检查，按四维（security / ai-cost / efficiency / design）输出带严重度、位置、三语文案的 finding；Builder 与外部开发者共用这一份。

**Architecture:** 新命令 `scripts/ptx-audit.mjs`（CLI 外壳 + 文案合并 + 退出码）调用 `scripts/audit/run.mjs` 的 `runAudit()`；`run.mjs` 用 TypeScript 编译器 API 把扫描目录下的 TS/TSX/JS 解析成语法树（不做类型检查），交给 `scripts/audit/rules-*.mjs` 里按维度分组的规则；每条规则只产出 `{ rule, file, line, args? }`，文案由 `scripts/audit-rules.json` 按语言补。与 `ptx doctor` 平级，不并入它。

**Tech Stack:** Node 22 ESM、`typescript`（starter 已有 devDependency，运行时从 `--root` 的 node_modules 解析，解析不到用脚本自身旁边的）、`node --test`。

**Spec:** `/Users/ao/work/gitlab/custom-app/custom-app-builder/docs/superpowers/specs/2026-11-06-builder-self-check-design.md` §2.1、§3（含 §3.1、§3.2）、§8。

## Global Constraints

- 分支从 `origin/main` 拉（本地 checkout 停在旧分支，不要在它上面开）；发 `next-*` 预发 tag，不动 `v3.*`。
- 退出码：有 severe → 2；只有 normal → 1；没有 → 0；跑不起来（typescript 解析不到、root 不存在）→ 3 并把原因写到 stderr。
- 规则条目与严重度照 spec §3 的表，不删条目；检测细节以「不误报」为先，拿不准就不报。
- 缺省扫描目录：`web/src`、`backend/src`、`shared`；`--src <dir>` 可重复、给了就只扫给的；永远跳过 `node_modules`、`dist`、`.out`、`.wrangler`。只扫 `.ts .tsx .js .jsx .mjs`；输出里列出 `scanned`（扫过的目录）与 `unscanned`（见到但不扫的语言：`.py .go .rb .php .java`，按扩展名统计，去重）。
- 文案语言：`PTX_LANG` ∈ `zh-CN | en-US | ja-JP`，缺省 `en-US`；`--json` 输出三语全带。
- finding 的 `id` = `<rule>:<file>:<line>`（file 是相对 root 的 POSIX 路径；没有行号的规则用 `0`）。
- 不联网、不写文件、不改项目。

## Review Focus

- 项目里有语法错误的文件：解析不应抛出；该文件记进 `unparsed`，其余照扫（Task 2 的测试）。
- `--root` 指向的项目没有 `manifest.json`：manifest 相关规则（SEC-002 / SEC-005 / AI-002 / DES-001 / DES-002）跳过，其余照跑，不报错（Task 2）。
- 同一文件同一行命中同一规则多次（如一行里两处 `eval`）：只出一条（Task 2 的去重测试）。
- 循环判断要穿过箭头函数：`rows.map(r => ctx.pt.ai.chat(...))` 是循环内调用，`rows.map(r => r.id); await ctx.pt.ai.chat(...)` 不是（Task 4）。
- `web/dist` 不存在（没 build 过）时 EFF-004 跳过，不报错（Task 5）。

**Interfaces:**
- Produces（`scan.mjs`）：
  - `collectFiles(root, srcDirs): { files: { abs, rel, area: 'web'|'backend'|'shared'|'other' }[], unscanned: string[] }`（area 按 rel 的第一段：`web` / `backend` / `shared`，其余 `other`）。

  - `parseFile(ts, file): { sf: ts.SourceFile, text: string } | null`（用 `ts.createSourceFile(rel, text, ts.ScriptTarget.Latest, true, kind)`，kind 按扩展名；`sf.parseDiagnostics.length > 0` → 返回 null）。
  - `walk(ts, node, visit: (n) => void)`：深度优先。
  - `callee(ts, node): string | null`：`CallExpression` 的被调用者文本，`PropertyAccess` 链拼成 `a.b.c`，`this.x` 原样；不是调用返回 null。
  - `insideLoop(ts, node): boolean`：向上找到 `for / for-of / for-in / while / do` 语句体，或作为 `map / forEach / flatMap / reduce / filter / some / every` 调用的实参的函数（箭头 / 函数表达式）内部 → true；遇到普通函数声明边界（不是上述回调）停止。
  - `enclosingRouteKey(ts, node): string | null`：向上找到 `PropertyAssignment` 且其父是 `createApp({ routes: {...} })` 的 `routes` 对象 → 返回键名（如 `'POST /jobs/daily'`）；否则 null。
  - `lineOf(sf, node): number`（1 起）。
  - `stringLiteralsIn(ts, node): { text, node }[]`：节点内所有字符串 / 无插值模板字面量。
- Produces（`run.mjs`）：`AuditContext = { root, ts, files: ParsedFile[], manifest: object | null, backend: { enabled: boolean } , distChunks: { file, bytes }[] }`，`ParsedFile = { rel, area, sf, text }`；`runAudit` 组装 ctx → 对 `rules-*.mjs` 导出的每条 `{ id, check(ctx): RawFinding[] }` 调用 → 去重（`rule+file+line`）→ 返回。manifest 用 `readManifest(root)`（`manifest.mjs`），读不到 → `null`；`backend.enabled` 用 `resolveBackend(manifest, root).enabled`；`distChunks` 读 `web/dist/assets/*.js` 的大小，目录不存在 → `[]`。
